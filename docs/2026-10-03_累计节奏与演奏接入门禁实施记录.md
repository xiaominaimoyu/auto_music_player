# 累计节奏与演奏接入门禁实施记录

## 结论与范围

已执行时值来源复核、累计节奏目标实现、12 组 CUDA pilot、原始预测→安全整形→实际编译器事件的离线对照，以及 CPU 重复推理验证。6 个候选系列均未通过采用门槛，因此不接入生产演奏、不开放实验 GUI、不全量重训、不发布新 EXE。本轮没有发送键盘/鼠标输入，没有修改 `core/`、`gui/` 或 Android，也没有执行 Git 提交或推送。

这些是 train/validation 开发域结果，不是最终盲测、真人听感或实机游戏验收。原数据、native masks、旧模型和历史报告保持不变；新权重、参考层、日志与事件轨迹均外置 E 盘。

## 1. 实现和受控实验

`rhythm_objective.py` 新增基于谱面物理秒数的累计间隔损失：对连续 1/8/32 个有效 IOI 的相对累计时长误差计算 SmoothL1，各可用跨度等权。它不是 1/4/16 **真实小节**监督；真实小节仍用于评估，慢 tempo 曲线与局部残差显式分头也尚未实现。不能将本轮写成“累计节奏问题已经修好”。

窗口不跨样本；只监督 disjoint core，排除 padding、halo、无效间隔以及 core 首个跨界 IOI。标签仍移除演奏者全局速度，oracle scale 不进入输入；目标不截断，指数运算明确限制预测并检查有限性。累计权重默认 0，旧 checkpoint/config 兼容；新增 `micro_weight` 可关闭失败目标，其他目标允许零权重，所有监督同时关闭则报错。累计监督与打乱标签负对照组合被拒绝，不伪造有效负对照。

| 因素 | 本轮固定条件 |
|---|---|
| 数据 | 原有锁定 train 244 / validation 24；quality mask 不启用；test 不读取 |
| 模型与预算 | MLP64 / 双向 GRU64；各 5 epoch、3 seed：20261003/04/05，共 12 组 |
| 窗口与优化 | core128/context16、batch32、dropout0.1、AdamW lr0.001 / weight decay0.0001 |
| 监督 | duration=1、IOI=1；micro/onset/velocity/pedal=0；累计权重 0 或 0.5 |
| 早停 | patience5；每组独立保留其目标下最佳 validation checkpoint |
| 比较 | 同输入、同样本、同训练预算；不宣称参数量相等；不同目标的总 loss 不能直接比较 |

12 组均完成。单组训练及原始预测审计约 21–36 秒；Torch 峰值 allocated 约 39–70 MiB，不是整机 GPU 占用。新增累计目标没有形成稳定收益：GRU 的作品等权 raw log-IOI MAE 从 0.174638 到 0.175342，配对差 +0.000704，95% 作品 bootstrap 区间 [-0.001049,+0.002431]；raw log-duration 从 0.643232 到 0.643592，区间也跨零。

三种子和作品重采样只支持这些固定 seed 下的开发域诊断，不覆盖全部 seed 不确定性；没有依据本轮验证集选择新门槛或最优 seed。

## 2. 时值与踏板语义复核

独立 `audit_duration_reference.py` 验证原始 ZIP 三元组成员 SHA、来源索引、分片 native mask、note-to-chord 和目标绑定。268 个样本、717,583 个谱面音符全部完成；train / validation 的 native duration 分别 597,457 / 74,038。

| 验证集观察 | 数量 / 含义 |
|---|---|
| 原时值标签数学回代最大误差 | 0.001386 ms；不是音乐对齐准确率 |
| 时值比在 0.4–1.6 以外 | 30,166 / 74,038，约 40.75%；当前试听限幅会改变这类目标 |
| 键保持短于 40 ms | 4,696，约 6.34%；当前保持下限会改变这类目标 |
| CC64 逻辑延音晚于 key-up | 39,745，约 53.68%；二者不可混成一个时长 |
| singleton micro | 17,062 条，全部为 0；不能把这类恒零目标表现当多音和弦能力 |
| 同音高 sustain 再触发歧义 | 16,795；诊断标记，不自动 mask |

未发现此集合的 duration floor/单 tick 标签问题。回代精确只证明标签公式与保存流程一致，不证明 MP3 转 MIDI 或音符对齐无损。无踏板记录保留未知，缺少 pedal-up 保留删失；CC64 结束也不是实测声学衰减。首轮工程审计因实现变动被标记 `_INCOMPLETE`，正式只使用 `duration_reference_244_24_20261003_v2`。

## 3. 原始预测、安全计划与游戏事件

新增 `shadow_expression.py` 只调用纯 IR/compiler，不加载输入驱动。模型预测来自 score-only；micro、velocity、pedal 不用于此候选。原谱 MIDI 的 tempo 积分秒数保持不变，`bpm=120` 仅作 IR 单位换算。

安全计划固定 strength0.5、log-IOI ±0.25、时值比0.4–1.6、40ms保持下限和 ±150ms score-only 累计起音预算；150ms 是保守工程旋钮，不是“人类演奏必须如此”的标准。实际 compiler 仍应用 max_hold3000ms、修饰键准备/释放和 FreePlay 约束。请求 gap0 经场景下限变为 **20ms**；原生规则 min_gap1.5ms，model/identity 为1ms。必须记录有效参数，不能只记录请求值。

适配器按绝对目标时间换算旧 compiler 的 offset，另保护完整鼠标释放边界，防止旧 up 排到新 down 后。最终 v3 显式保证“全部键/修饰键释放→下一音开始准备”至少 `max(gap_ms,min_gap_ms)`，不允许负 offset 抵消 FreePlay 的20ms下限。原谱静默考虑此前仍持续的低音，避免制造错误休止/呼吸。非有限、非法形状、不可表达的琶音路径等直接失败，不静默补值。

对照包含原生 identity、原生 `HumanizeParams` 规则、全零预测 model adapter，以及历史 matched MLP/GRU 三 seed。零模型控制区分“适配器抵消固定延迟、改用所选键长”与学习收益。

下表为最终 v3 投影后 fixed-score **真人参考重建误差**，单位 ms；作品内 event/window 加权、23 个来源作品单元等权、3 seed 平均。作品键为 `performance_dataset::piece_group`，不能自动视作跨来源独立音乐作品。只评价游戏折叠后所选单声部，不是完整钢琴演奏，也不是实机调度延迟。

| 原生 identity | 67.19 | 209.88 | 588.62 | 2137.27 | 4888.88 |
| 原生规则 | 65.37 | 221.56 | 582.98 | 2112.75 | 4397.48 |
| 零模型适配器 | 68.80 | 209.59 | 590.61 | 2140.61 | 5109.33 |
| 历史 matched MLP | 66.39 | 207.02 | 585.34 | 2120.08 | 4240.87 |
| 历史 matched GRU | 66.87 | 206.92 | 597.57 | 2165.26 | 4224.21 |
| 新 MLP，局部损失 | 66.74 | 207.07 | 587.37 | 2120.69 | 4263.97 |

新 GRU 累计候选相对零模型：IOI 约改善2.65%，配对差区间 [-5.47,+1.51]ms；保持误差约改善1.59%，区间 [-8.14,+1.21]ms；1小节误差增加约8.65ms，区间 [-35.69,+61.68]ms。相对原生规则 IOI 仍退化约2.46%；不足以支持整体采用。

39,488/39,488 是**和弦起音覆盖**。79,465 个来源音符中 39,977 个声部未表达，15,966 个音符发生八度折叠；最高音按折叠后的 IR 排序，不保证是原始 MIDI 最高音。各对照共享此投影，不能将这些损失归因于模型，也不能据此宣称完整谱面保真。

安全 desired 在预算内不等于最终事件在预算内。新 GRU 累计候选三 seed 共 109,217 个 chord-run 起音超过 ±150ms，但完整释放后20ms间隔违规为0；这是重放同一验证集合的编译计划计数，不是独立样本数或实机测量。早期投影独立重算三个样本指标残差 <6e-14；最终 v3 独立重放全部432条存储轨迹、710,352次释放→准备转换，事件链错误、残留按键、低于20ms的间隔违规均为0（浮点容差）。

原生 identity/rules 未修改。原生规则 seed20261003 有211个准备间隔低于20ms，已保留诊断；严格 model 路径比该原生路径更保守，不宣称这些差异构成“纯模型因素”的因果对照。下一轮增加同物理约束的规则适配器对照，不能放松模型安全来匹配。

## 4. 接入门禁与 CPU 验证

`playback_adoption.py` 固定当前讨论的严格工程目标：至少3个不同 seed；相对 identity/规则/零模型，投影后 IOI 与保持主指标改善至少10%，作品95%区间支持改善且每 seed 方向一致；1/4/16小节不退化；每来源至少5作品、无超过2%的均值退化；安全/覆盖合格。此门槛用于当前开发域预筛，不是行业标准，也不代替真人偏好和最终盲测。

全部6个系列失败。ATEPP、Aria-MIDI 各只有2个作品，来源证据不足；ASAP5、GiantMIDI-Piano6、PERiScoPe8。新 GRU 累计候选相对原生规则，在 ASAP / GiantMIDI-Piano 的 IOI 均值分别退化约3.58% / 4.58%，不能通过来源预筛。门禁拒绝重复 seed、遗漏来源/对照和缺失窗口，不用交集偷偷缩小覆盖；完整 inventory 与 parent-child/sidecar/checkpoint 绑定均核验。即便数字通过，也不会自动创建 GUI 入口或开启生产演奏。

CPU 基准预先选用 GRU累计/seed20261003，不选择最好 seed。24 个 score-only 样本将 targets/masks 清零，不提供 oracle 几何；4 CPU线程、暖机后单次推理中位51ms、p95147ms、最大154ms，加载约16ms；重复结果逐位一致。这不包含完整导入/编译/GUI流水线，不证明暂停、续播、停止、超时回退或 GUI 响应。

本轮模型仍仅用于研究。真人偏好仍为0，原3题启动包未改写；自动化答卷不计入真人。旧 test 已在历史阶段观察过，不能重新包装成从未触碰的最终盲测。

## 6. 下一轮实施顺序

1. 先审计**游戏可表达性**：按档位区分单声部、21键与修饰键模型，列出最小 IOI、键保持、修饰切换及 octave/chord 降级；以可表达区域设计训练/评估投影，不通过取消安全间隙获得虚假收益。当前 shadow 不是生产 MIDI importer，也不是 legacy Player 验收。
2. 在新开发集合事前固定评估口径：区分真人全局速度差、score-tempo 下的表达残差与执行器约束。当前 fixed-score 绝对真人参考误差会包含全局速度差；oracle 诊断不证明模型能恢复该速度，也不能事后换指标宣布本轮通过。
3. 构建来源与作品更均衡的 train/validation 开发集合，至少补齐每来源5作品，优先更具代表性的非标记样本；建立真正未触碰的独立盲测集合。当前244/24集合由质量诊断产生，不能代表全部用户谱面。
4. 再做慢 tempo 曲线/局部残差分离、真实小节累计监督与可表达键长目标；一次只改变一个因素，保留 matched MLP、零模型适配器、负对照和3 seed。不先扩大模型或全量重训。
5. 保留原真人回收链，扩展至少5个独立许可清晰作品后组织真实盲听；数值/投影过门后才单独实施 CPU后台预计算、超时/异常规则回退、暂停/停止释放，再评审默认关闭实验入口。实机游戏、默认启用、Release、Android 分别验收。

人工决策仍需：真实回收渠道与同意范围、独立盲测/游戏可表达样本的来源；未替用户发布材料或作外部协调。
