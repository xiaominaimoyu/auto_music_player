## 1. 关键设计决策（评审重点）：**新增 `EventPlayer`，不改造现有 `Player`**

总计划 §7 写的是"改造 `core/player.py`"。**我建议改为新增独立类**，理由如下：

| 方案 | 对鸣潮/原神的回归风险 | 结论 |
|---|---|---|
| A. 改造 `Player`（加事件模式） | **中–高**：同一类里两条路径，调度逻辑必须动刀 | ❌ 不推荐 |
| **B. 新增 `EventPlayer`**（推荐） | **零**：默认 21 键路径**一行不改、一个字节不变** | ✅ |
| C. 抽取公共调度基类，两个子类 | 低–中：依然触碰 `Player` 的既有逻辑 | 列为**后续重构**，不在本次 |

**选择 B**。M4 是全计划唯一碰演奏核心的里程碑，把它对老游戏路径的影响降到**字面意义的零**，
比少写 ~80 行调度代码更值得。`EventPlayer` 复用 M1 的 `KeyboardDriver`（含 `panic_release`），
只复制绝对时钟调度这一小段经过验证的逻辑。

> **后续重构提示**：M4/M5 稳定后，可把 `Player` 与 `EventPlayer` 的公共调度抽为基类
> （届时 `player.py` 的既有测试与 `event_player.py` 的新测试会各自约束两侧）。

## 2. `core/event_player.py`

### 2.1 职责

把 M2 编译出的 `InputEvent[]` 按绝对时刻逐一发送给驱动；
支持从任意事件索引续播；中断时**连同鼠标键一起释放**。

### 2.2 接口（概念）

```python
class EventPlayer(QObject):
    progress       = pyqtSignal(int, int)   # 已完成事件数, 总数
    finished       = pyqtSignal(bool)       # 自然结束(True) / 出错(False)
    paused         = pyqtSignal(int, int)   # 可恢复暂停: 已完成, 总数
    aborted        = pyqtSignal(str)        # 【新增】不可恢复中止: 原因
    error_occurred = pyqtSignal(str)

    def __init__(self, driver, latency_compensation_ms=0, parent=None)

    def play(self, events, interrupt_mode="pause", start_index=0, score_name="")
    def stop(self)          # 按 interrupt_mode 决定 pause 还是 abort
    def abort(self, reason) # 强制中止(清空进度, 释放全部, 发 aborted)
    def shutdown()          # 退出兜底
```

### 2.3 核心机制

| 机制 | 说明 |
|---|---|
| **绝对时钟调度** | `t0 = perf_counter() - events[start_index].t_ms/1000`；每个事件目标时刻 = `t0 + e.t_ms/1000 - comp` |
| **事件分发** | `device="kb"` → `press_key`/`release_key`；`device="mouse"` → `press_mouse`/`release_mouse` |
| **停止响应** | 等待用 `Event.wait`，可在 100ms 内被打断（沿用现有语义） |
| **续播** | `paused(done, total)` 带出 `start_index`，下次 `play(..., start_index=done)` |
| **释放兜底** | 结束 / 暂停 / 中止 / 退出 → `driver.panic_release(keys, mouse_buttons)` |

### 2.4 释放集合怎么来（**关键点**）

`_release_all` 不能依赖外部传入的键位清单（M4 不与 profile 耦合）。**直接从本次播放的事件里推导**：

```python
keys  = {e.key for e in events if e.device == "kb"}
mouse = {e.key for e in events if e.device == "mouse"}
panic_release(keys, mouse)
```

> 这样无论档位怎么配，只要事件在这一把里出现过，就保证被释放——
> 不需要知道「口琴用哪几个键」，也不会漏掉修饰键（M1 遗留的 `_release_all` 只释放键盘的坑，在此彻底闭合）。

### 2.5 `pause` / `abort` 双语义（UC-8 / UC-9）

| 语义 | 触发 | 行为 | 场景 |
|---|---|---|---|
| `pause` | `stop()` 且 `interrupt_mode="pause"` | 释放全部，`paused(done, total)`，**可续播** | S1 自由演奏 |
| `abort` | `stop()` 且 `interrupt_mode="abort"`，或显式 `abort(reason)` | 释放全部，**清空进度**，`aborted(reason)`，**不可续播** | S2 NPC 任务 |

**为什么 S2 必须 abort**：调研确认 NPC 任务被打断后**手动重新掏出口琴也不能提交曲谱**，
必须重新听 NPC 示范。因此 S2 的任何中断（F8 / 失焦 / 错误）都直接中止并提示重来，
"断点续播"在 S2 是没有意义的。

## 3. `core/scenario.py`

### 3.1 场景计划

```python
@dataclass(frozen=True)
class ScenarioPlan:
    events: list          # 音符事件 [+ post_roll], 已按时刻排好
    interrupt_mode: str   # "pause" | "abort"
    abort_hint: str       # 中止后给用户的中文提示
```

```python
        # events = music_events            ← 无 pre-roll,口琴由用户手动启用

class NpcQuestScenario:
    def plan(self, music_events, submit_key="Q") -> ScenarioPlan
        # interrupt_mode = "abort"
        # abort_hint = "演奏被中断，请重新听 NPC 示范后再演奏"
        # events = music_events + post_roll(Q down/up)
```

### 3.3 口琴启用：**用户手动，程序不做任何自动切换（修订）**

**已移除自动 pre-roll（程序按 `6` 唤出 EDC 轮盘选口琴）。**

| 场景 | 口琴如何就位 | 程序行为 |
|---|---|---|
| S1 自由演奏 | **用户手动从背包/EDC 启用口琴**后，再点开始演奏 | 无任何 pre-roll；倒计时结束后直接弹第一个音 |
| S2 NPC 任务 | NPC 示范后**自动装备** | 无需任何 pre-roll；post-roll 为 `Q` 提交 |

**为什么删而不是留作可选**：
- pre-roll 是**盲发无反馈**（不与游戏交互），打空/打错都没法检测，还要为"槽位在哪个格"做可配置——复杂度和失败率都不值
- EDC 槽位由用户装配决定，自动序列必然无法写死
- 让用户先手动启用，把"是否就绪"的判断权交回给人，**最稳、最简单**

**对应的用户流程**（GUI 提示文案照此写）：
```
1. 进游戏，手动从背包/EDC 把口琴拿在手里
2. 回到本工具，选档位 + 乐谱，点开始
3. 倒计时期间切回游戏窗口
4. 程序直接开始演奏
```

> 现有演奏控制页已有**3 秒倒计时**——S1 把"切出口琴 + 切窗"都放进这段时间由用户完成即可；
> 若嫌短，倒计时秒数本来就应可配（沿用现有参数，不在本次新增）。

### 3.4 post-roll

`NpcQuestScenario` 末尾追加：`Q down → hold 80ms → Q up`。

### 3.5 音符间隔（D6）

| 场景 | `modifier_settle_ms` | `min_gap_ms` |
|---|---|---|
| S1 FreePlay | 30（config 默认） | 20（config 默认） |
| S2 NpcQuest | **60** | **120**（识别友好：宁可慢、不可叠键） |

S2 的间隔在**组装 `CompileParams` 时覆盖**，而不是改编译器。

## 4. 完整数据流（M4–M5 打通后）

```
谱面 notes_json
  └─ ir.from_storage()            → IRNote[]
  └─ profile.build_compile_params() → CompileParams
  └─ compiler.compile_score()      → CompileResult(events, degradations)
  └─ scenario.plan(events)          → ScenarioPlan(音符 [+ post_roll], interrupt_mode)
  └─ EventPlayer.play(plan.events, plan.interrupt_mode)
  └─ KeyboardDriver (SendInput)

S1: 用户手动从背包/EDC 启用口琴 → 倒计时 → 直接演奏（无任何自动切换）
```

**降级清单** `CompileResult.degradations` 随结果带出，GUI 汇总计数并支持导出（UC-12）。
