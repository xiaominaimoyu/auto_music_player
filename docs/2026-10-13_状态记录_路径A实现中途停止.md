## 关键发现：路径 A 的"共享剖面臂"实际上没有生效，产物不可当证据

三 seed 已训完（`v4/shared_profile_20261011/shared_seed20261003..5`，`_SUCCESS` 齐全，best_validation_loss 0.3305/0.3274/0.3276，参数 52,872 与无形状块的对照一致）。但 run_config 里：

```
duration_target = shared_profile   duration_center_per_sample = True
shared_profile_coverage.share_shared = 0.0
```

**也就是说没有任何一条录音拿到共享目标**，这三个臂在数值上就是"每曲居中"对照臂的复制品，不能用来回答"换监督目标有没有用"。根因不是代码 bug 而是**数据选择**：开发用的 `development_balanced_250_50_20261003` 是按作品组去重抽的，**每个作品组只有一条录音**，于是 `shared_duration_targets` 对每个成员都判为 `alone in this split` 并回退到自身标签。跨演奏平均在这个子集上定义不出来。

我在 23:00 前后给 trainer 加了一条硬失败守卫（`shared_recordings == 0` 直接 `TrainingRunError`，并把 coverage 打进错误信息），就是为了不让这种"静默等价于对照"的臂再次以实验身份出现。**这份守卫还没有对应的测试用例**（现有 13 例覆盖库函数与 CLI 落参，没覆盖这条），接手时请补。
