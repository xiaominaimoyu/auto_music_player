## 2. API 设计

### 2.1 新增常量

```python
INPUT_MOUSE = 0

MOUSEEVENTF_LEFTDOWN   = 0x0002
MOUSEEVENTF_LEFTUP     = 0x0004
MOUSEEVENTF_RIGHTDOWN  = 0x0008
MOUSEEVENTF_RIGHTUP    = 0x0010
MOUSEEVENTF_MIDDLEDOWN = 0x0020
MOUSEEVENTF_MIDDLEUP   = 0x0040

MOUSE_BUTTONS = ("left", "middle", "right")
```

### 2.2 构造参数（settle 可配）

```python
KeyboardDriver(settle_ms=30.0, release_settle_ms=20.0)
```

| 参数 | 默认 | 依据 |
|---|---|---|
| `settle_ms` | **30.0** | 计划 §6.3 `modifier_settle_ms`。参考实现硬编码 5ms，大概率不足以让游戏注册修饰态 |
| `release_settle_ms` | **20.0** | 计划 §6.3 `modifier_hold_ms`：音键 up → 修饰键 up 的间隔 |

- 两者均允许 **per-call 覆盖**（`press_combo(..., settle_ms=None)` 时回落到实例默认）
- 校验：`< 0` 抛 `ValueError`；上限不设（由配置层把关）
- `CHORD_INTERVAL_MS = 5` **保留不动**，仍用于和弦内多键间隔（与 settle 是两回事）

### 2.3 新增方法

| 方法 | 语义 |
|---|---|
| `press_mouse(button)` | 按下鼠标键 |
| `release_mouse(button)` | 释放鼠标键 |
| `press_combo(key, mouse=None, settle_ms=None)` | **mouse down → settle → key down** |
| `release_combo(key, mouse=None, release_settle_ms=None)` | **key up → release_settle → mouse up** |
| `panic_release(keys=(), mouse_buttons=())` | 兜底全松；逐项 try/except，**永不抛异常**（供 M4 `_release_all` 用） |

### 2.4 顺序约定（正确性硬约束）

```
按下： [mouse down] ──settle_ms(30)──→ [key down]
松开： [key up] ──release_settle_ms(20)──→ [mouse up]
```

**为什么松开必须"先键后鼠"**：调研确认鼠标修饰态是 latch-while-held，不松开则后续音持续被转调。反序会让**最后一个音被错误转调**。参考实现这一点做对了，沿用。

### 2.5 错误处理

| 情况 | 行为 |
|---|---|
| 未知 button（非 left/middle/right） | `ValueError`，**不静默** |
| `SendInput` 返回 ≠ 1 | `OSError`，带 `winerror` 与 button 名 |
| 非 win32 平台 | 沿用现有 `_load_user32()` 延迟抛 `OSError` |
| `panic_release` 内部 | 逐项吞异常，保证尽力释放 |

## 3. 配置项

`config.yaml` 的 `player:` 段新增（**带注释，默认值即推荐值**）：

```yaml
player:
  # 鼠标修饰键按下 → 音符键按下 的最小间隔(毫秒)
  # 参考实现用 5ms,实测很可能不足以让游戏注册修饰态,取保守值 30
  modifier_settle_ms: 30
  # 音符键松开 → 鼠标修饰键松开 的间隔(毫秒)
  modifier_release_ms: 20
```

`main.py`：读取这两项 → 构造 `KeyboardDriver(settle_ms=..., release_settle_ms=...)` → 注入 `Player`。

> M1 阶段 `Player` 尚不使用 combo，因此**行为无变化**；此处提前接线是为 M4 铺路，避免届时再动 `main.py`。

## 5. 测试用例（新增 `tests/test_input_driver_mouse.py`）

**Mock 策略**：monkeypatch 模块级 `_user32` 为 stub。`SendInput(n, byref(inp), size)` 的 stub 通过
`byref` 对象的 `_obj` 属性回指原 `INPUT` 实例（避免为可测性改动生产代码），读取 `inp.type` 与
`inp.mi.dwFlags` / `inp.ki.wScan`，记录调用序列。

> 实测落地 **22 个用例**（原计划 12 个，拆细了边界：左右键标志位各一组、非数字 settle、
> 发送失败、完整往返顺序、和弦间隔未受污染等）。

| # | 用例 | 断言 |
|---|---|---|
| 1 | `_MOUSE_FLAGS` 映射完整性 | 6 个组合全部存在且互不相同 |
| 2 | `press_mouse("middle")` | flag == `0x0020` |
| 3 | `release_mouse("middle")` | flag == `0x0040` |
| 4 | `press_mouse("unknown")` | 抛 `ValueError` |
| 5 | `KeyboardDriver(settle_ms=-1)` | 抛 `ValueError` |
| 6 | `press_combo("Z", "right")` 调用序列 | `[right_down, Z_down]`，且两步间隔 ≈ `settle_ms` |
| 7 | `release_combo("Z", "right")` 调用序列 | `[Z_up, right_up]`（**顺序是正确性断言**） |
| 8 | `press_combo("Z", None)` | 只发 `Z_down`，不发鼠标事件 |
| 9 | per-call 覆盖 | `press_combo("Z","right", settle_ms=50)` 覆盖实例默认 30 |
| 10 | 非 win32 平台 | monkeypatch `sys.platform` → 抛 `OSError` |
| 11 | `panic_release` 幂等 | 重复调用不抛；单个项目失败不影响其他项 |
| 12 | **回归**：`press_key("Q")` 事件与改造前一致 | 快照断言（wScan + flags） |
