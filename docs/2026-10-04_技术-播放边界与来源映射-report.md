# 播放预处理边界修复与来源映射

日期：2026-10-04。范围：Windows 桌面播放预处理、PianoCoRe 开发集来源追踪与训练前审计。

已修复短片段吸收后超过 16 拍的播放拒绝，完成相同 300 个样本的重新投影和来源映射。600 个 sample/style 案例中 598 个完成，另 2 个继续按现行 30 分钟导入上限拒绝。新增 mask 仅表示原生标签来源候选，未写入训练加载器，未启用模型演奏。本轮没有 GPU 训练、真实游戏输入、Android 修改、打包或 Git 提交/推送。

## 1. 已实施的改动

### 播放预处理边界

`core/transport.py` 在短片段吸收后统一切分超过 16 拍的元素，并在处理前校验所选原始片段，避免非法时值被合并或移调掩盖。

- 尽可能保留原有 16 拍分段；若末段不足最短演奏时值，只从前段借足差额。例如 120 BPM、60ms 门限下，16.04 拍拆成 15.92 + 0.12 拍，不产生新的极短尾段。
- 保持存储总拍长、音高、和弦与半音，降级记录仍指向原始片段绝对索引。全曲总长不足最短门限时保留原长，不补造时间；空谱仍可处理。
- **切分长音会重新触发，不是延音连线。** 存储时间轴保持不变，不表示加入按键间隔、修饰键等待后的实际墙钟时长不变。休止切分不触发按键。

修复样本 `PianoCoRe_020138` 的 piano/preserve 路径均由 `transport_rejected` 变为 `complete`；最后约 1ms 片段曾使相邻元素达到 16.0021 拍，两条新路径的存储时间轴终点误差均为 0ms。其余 598 个案例与旧 v2 的文件哈希完全相同。`PianoCoRe_239544` 的两个拒绝继续保留，未放宽 30 分钟策略。

### 保守的来源旁文件

新增 `training/source_game_mapping.py` 与 `training/audit_source_game_mapping.py`，不改变原始 MIDI、shard、native targets/masks 或旧 checkpoint。

| 边界 | 实际处理 | 不可直接复用的情况 |
|---|---|---|
| native parser → production reader | 同一已绑定 MIDI；音高、起音、抬键端点双向唯一匹配，容差 1e-7 秒 | 跨轨 FIFO 差异、重复端点歧义、生产侧丢弃的零时长音符 |
| 来源 → 导入存储 | 复用适配器的选轨和 segment.members，重放后逐项核对真实适配结果 | 削减声部、截取、桥接、折八度、移调、混合半音和弦降级、去重、长音拆分 |
| 导入 → 60ms 预处理 | 只有完整片段音高与端点不变才传播严格身份 | 吸收、移动、拆分或多来源重叠 |
| 预处理 → 档位逻辑投影 | 分开走默认 legacy 与 Delta 自由演奏机械链 | 档位删音、和弦降级、半音/八度改变或端点变化 |

未知 native 索引为 -1；另存原始来源候选的变长索引及原因。不能仅按折叠后音高或新序号猜回旧标签。来源匹配按整批双向唯一性计算，不采用逐音符贪心分配。

输出中 `native_note_masks`、`native_chord_masks`、`native_note_to_chord` 是原参考数组的独立副本。各阶段同时保存 source/native/element 索引、音高、起止时间、严格标志、原因和候选来源。

三类候选 mask 的边界：

1. `duration_candidate_mask`：严格身份且原生时值 mask 有效；只说明标签来源，未验证 hold/gap 或时长比例约束。
2. `singleton_duration_candidate_mask`：在上项中排除共享按住时长的多音和弦；仍不是实际调度可行性 mask。
3. `ioi_candidate_mask`：当前和前一个发声组均完整对应原生和弦，必须是连续 j-1→j，两个端点 trusted 且原生 IOI mask 有效。首组恒为 false；删去中间和弦后不能套用旧单间隔标签。

审计只接受绑定的 train/validation、完整 sample×style 笛卡尔积和当前代码/配置指纹。拒绝案例保留在分母；内部异常不伪装成数据拒绝。封存前重验原 ZIP 成员、参考、游戏审计、实现与输出文件，失败保留 `_INCOMPLETE`。

真实数据还暴露了 ZIP 曲名包含冒号的兼容性问题。现在允许合法 ZIP 字面名称，但仍拒绝绝对路径、盘符、反斜杠、`..` 和 NUL。成员名只传给 `ZipFile.read`，不按其名称解压；临时 MIDI 使用固定文件名。已有真实冒号目录格式的整链回归。

## 2. 300 样本真实审计结果

沿用五来源均衡 250 train / 50 validation；这是开发集合，不是新的盲测。每个样本分别执行 piano、preserve，两档位结果存于同一案例旁文件。

- 游戏审计 v3：598 complete、2 import_rejected、0 transport_rejected；299/300 个样本两种 style 均完成。
- 来源映射：相同分母与拒绝原因；600 份案例 JSON、598 份 NPZ、summary 与完成标记，共 1,200 个文件，74,655,130 字节。
- 主代理逐份检查文件集合/哈希、22 个实现与配置绑定、native 数组相等、严格索引唯一性、阶段子集关系、候选来源索引、三类候选 mask 的重算结果和分组汇总，全部通过。
- 2,392 个 Delta compiler 投影的事件配对错误与残留按键为 0；这是纯编译器检查，不是实际键盘、游戏或音响验收。legacy 仍为静态时间轴分析。

验证集的候选覆盖如下。斜线后分别为对应档位的投影音符总数、发声组总数；不是原生音符分母，也不是模型准确率。

这套门禁比旧端点保留统计更保守：即使保留下来的最高音恰好起止不变，删声部等变形仍被排除；IOI 还要求完整原生和弦。不能将覆盖下降解释为模型退步，也不能把全部原生钢琴标签当成游戏已能表达的目标。

## 4. 下一步与验收条件

1. **真实小节窗口及辅助损失。** 接入既有 `bar_supervision` 几何，显式覆盖 1/4/16 小节端点和最多 512 chord 的容量；窗口归属、halo/padding 排除、输出唯一归属必须可测，训练与推理使用一致上下文。旧 128 core 的验证集 16 小节覆盖不足问题仍需实现解决。
2. **tempo/local 目标分解。** 在原生域保持可信监督，设计可识别的慢速度与局部节奏分量；游戏域仅单列本轮可追溯子集，并进一步叠加真实编译预算检查。候选 mask 不能直接当作实际可演奏 mask，不能将 performance、拟合整体速度或标签可信比例作为模型输入。
3. **先验证损失，再做 matched pilot。** 数值梯度、8–16 个 train 作品 tiny-overfit、train-only target shuffle 先通过，再运行固定新开发集合的 MLP/GRU 三种子对照。normalized-human 与 raw-human 分开报告，保留同执行约束的 identity/规则/零模型基线，不反复使用旧 24 条验证集调参，不降低历史采用门禁。
4. **收益稳定后推进试听与实际接入。** 扩充许可明确的真人 A/B 作品与参与者，最后验证真实游戏输入与听感。模型默认启用、正式发布与改变导入限制仍需单独评审；本轮不授权这些动作。

并行复核技能用于分离预处理、映射实现和独立证据检查，主代理整合并重跑验收；文档技能用于区分实施事实、证据、局限与后续行动。原始数据和用户既有未提交内容均保留，未操作 Git 暂存区。
