## 2. 阶段二：关键路径

### 2.1 M0 实机实测（用户操作，约 5 分钟）

> 源自需求分析计划 §M0；检查项 3（EDC 轮盘）已随 D5 取消。**结果直接决定 v1.1.2 是否需要改键位配置。**

**准备**：进入三角洲行动 → 装备「守夜人口琴」→ 进入口琴弹奏界面（自由演奏）。

**键位参考**（`profiles/delta_force_harmonica.yaml`）：

| 按键 | 音 |
|---|---|
| `Z X C V B N M` | 1 2 3 4 5 6 7 |
| 按住**鼠标左键** + 音位键 | 低八度（降调） |
| 按住**鼠标中键**（滚轮按下） + 音位键 | 升半音 |
| 按住**鼠标右键** + 音位键 | 高八度（升调） |
| `,`（M 右侧逗号键） | 高音 1（直达） |

**检查项**：

| # | 操作 | 记录什么 | 判据与后续动作 |
|---|---|---|---|
| 1 | 依次单按 `.` 和 `/` | 是否出声？出的什么音？ | 出声且音高明确 → 启用对应 `pitch_direct_overrides`（改 profile，D3） |
| 2 | **按住左键不松** → 再按住中键 → 敲 `Z` | 听到：低音 1 / 低音 1# / 没声？ | 若为低音 1# → 修饰态可叠加，改 `resolve_modifier`（D4）；否则维持互斥，零改动 |
| 3 | 查看「挽歌」表情动作入口 | 是否为独立键位/轮盘？ | 确认与口琴弹奏无关即可（D7 排除项） |
| 4 | 对比自由演奏与 NPC 任务界面的音符手感 | 按键反馈是否一致？ | 一致 → 维持音符层不 fork（D6） |

**结果记录表（实测后回填）**：

| # | 结果 | 结论 | 需改动 |
|---|---|---|---|
| 1a `.` | 待补充 | 待补充 | 待补充 |
| 1b `/` | 待补充 | 待补充 | 待补充 |
| 2 左+中叠加 | 待补充 | 待补充 | 待补充 |
| 3 挽歌 | 待补充 | 待补充 | — |
| 4 手感 | 待补充 | 待补充 | — |

## 4. 阶段四：中期 backlog（v1.1.2 后按需排期）

| 优先级 | 事项 | 说明 | 估时 |
|---|---|---|---|
| ⭐推荐 | **P1-3 键位自检模式** | 逐音试奏验证键位，把 M0 类人工验证变成程序闭环（新游戏适配提速） | 待评估 |
| 中 | P1-2 事件序列预览面板 | 无游戏环境下自检编译结果与降级清单 | 待评估 |
| 中 | P1-4 NPC 任务谱模板 | 6 首隐藏谱 | 待评估 |
| 中 | V2 半音启用 | parser 支持 `#` + 接通 `semitone_source="raw_text"`（IR/编译器已就绪，用户无需重新导谱） | 待评估 |
| 低 | P2-1 手游端支持 | 屏幕坐标输入管线（与键盘管线完全不同，可能复用安卓端标定经验） | 待评估 |
| 低 | P2-2 谱面分享增强 | 导入导出体验优化 | 待评估 |

**选择 P1-3 先行的理由**：本次 M0/M6 再次证明「键位对不对」只能靠人工进游戏验证；自检模式落地后，新档位适配（原神新乐器、其他游戏）的验证成本从「人工 5 分钟 + 记忆」降为「程序自动逐音回放比对」。
