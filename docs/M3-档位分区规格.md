## 1. 分区设计

| 分区 | 档位 | 输入模型 |
|---|---|---|
| **默认** | `default` | 21 个独立键（高/中/低 3×7），**不使用鼠标修饰键** |
| **三角洲行动** | `delta_force_harmonica` | 7 个音位键 × 4 种鼠标修饰态（四态互斥） |

> 需求原文："原本的鸣潮和原神保留并保存在与三角洲行动不同的分区"。
> 参考项目 `auto_music_player-main` 是**覆盖式**改造（直接改 `config.yaml` 的 keymap），
> 会让鸣潮/原神当场失效——本设计刻意避开这一点。

## 2. `core/profile.py`

```python
GameProfile(id, name, group, pitch_keys, modifier_buttons,
            pitch_direct_overrides, modifier_policy, chord_policy, legacy_keymap)
```

| 函数 | 职责 |
|---|---|
| `load_profiles(dir, fallback_keymap=None)` | 加载 `profiles/*.yaml`；**目录缺失/为空 → 用 `config.yaml` 的 keymap 合成 default** |
| `resolve_profile(profiles, id)` | 按 id 取；未知或为空 → 回落 default → 再不行取第一个 |
| `grouped(profiles)` | 按 `group` 分组，保持文件顺序，供 GUI 下拉分段展示 |
| `legacy_profile(keymap)` | 由旧 21 键 keymap 合成 default 档位 |
| `ensure_profiles(base_dir)` | exe 场景释放打包资源；**已存在则不覆盖**（保留用户修改） |
| `GameProfile.build_compile_params(...)` | 组装 M2 的 `CompileParams`，修饰态键名 str → `Modifier` 枚举 |

**默认档位如何用新模型表达 21 键**：全部走 `pitch_direct_overrides`（21 条），
`modifier_buttons` 为空 → 编译器不产生任何鼠标事件，与旧 `KeyMap` 行为**逐音符等价**。

## 3. 三角洲档位要点（`profiles/delta_force_harmonica.yaml`）

```yaml
pitch_keys: [Z, X, C, V, B, N, M]
modifier_buttons:
  lower: left      # 降调(低八度)
  semitone: middle # 升半音(滚轮按下)
  higher: right    # 升调(高八度)
pitch_direct_overrides:
  high_1: ","      # ✅ 已启用(中高可信)
  # high_2: "."    # ❌ 注释保留,待 P1-3 键位自检
  # high_3: "/"    # ❌ 无证据
modifier_policy: octave_first
chord_policy: first
legacy_keymap: null
```

- 标点直达**只启用 `,`**（D3）。注释里写明了 `.` `/` 的证伪理由，便于日后放开。
- `legacy_keymap: null` —— 三角洲没有 21 键旧模型，M4 必须走编译器路径。

## 4. 配置与回落（风险 R8）

`config.yaml` 的 `app:` 段新增：

```yaml
active_profile: default   # profiles/ 下的档位 id;填错或缺失回落 default
```

**回落链**：`profiles/` 存在 → 用它；否则用 `config.yaml` 的 `keymap` 段合成 default。
老的 `keymap:` 段**一行未删**，所以鸣潮/原神老用户的配置继续生效。

## 5. exe 打包（坑 C5）

| 改动 | 文件 |
|---|---|
| `datas` 增加 `("profiles", "profiles")` | `AutoMusicPlayer.spec` |
| 新增 `ensure_profiles()`：exe 旁不存在时才从 `_MEIPASS` 释放 | `core/profile.py` |
| 启动时调用 `ensure_profiles(".")` | `main.py` |

**为什么不能只靠 `datas`**：onefile 解压到 `_MEIPASS` 临时目录，退出即清理 →
用户改过的档位会丢。必须释放到 exe 旁并**不覆盖已存在目录**。
